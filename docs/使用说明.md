# 使用说明

## 1. 开始前

1. 启动平台并确认页面显示“服务正常”。
2. 仅连接本轮需要的测试设备；关闭手机 App、串口终端和其他可能占用设备的工具。
3. 先读取当前配置，再决定是否执行写入、联系人互识或通信验证。
4. 所有写入或发消息操作前，确认设备归属、区域设置和团队操作规范。

## 2. 串口操作

### 2.1 连接设备

在“测试执行”页选择串口连接，扫描 COM 口并分别选择主设备和对端设备。需要监听空口或角色行为时，可接入观察者设备。连接后先运行读取操作，确认设备身份、区域和关键配置。

### 2.2 配置写入

在“配置写入”区域选择目标设备和配置字段，填写目标值后执行。平台遵循“先读、必要时写、等待、读回”的流程：当前值一致时跳过写入，写入后必须以读回值确认结果。

### 2.3 联系人与通信

双设备通信前，可使用“建立联系人”完成互识。随后在“通信验证”中选择频道或点对点消息方式。通信结论应查看接收、ACK 或设备可见证据，不能只以发送命令返回成功判断。

## 3. BLE 操作

BLE 用于模拟用户连接单台设备后的真实使用链路：连接、读取配置、修改配置、持续收发和长连接检查。

- 当前一次只支持一台同类 Meshtastic 设备；这是本机蓝牙模块与浏览器 GATT 的并发边界。
- 长连接检查会在指定时段内周期性读取设备身份；只有连接持续存在且节点 ID 一致才通过。
- 该检查不等同于双设备 BLE 通信，也不替代手机 App 端到端体验测试。

## 4. 日志与报告

### 4.1 串口日志

在“日志”页选择日志串口和波特率，点击“开始监听”。页面会实时显示设备原始日志，并在本地 `logs/` 目录生成日志文件。出现重启、异常、收发失败或偶现问题时，应记录时间点并与报告中的步骤对应。

### 4.2 结构化报告

每次执行会在本地 `logs/` 目录生成 JSON 报告。报告页可查看或下载报告；重点检查测试项、步骤、命令、读回值、原始输出、PASS/FAIL/SKIPPED 状态及失败原因。敏感配置仍应在分享前人工复核。

## 5. 使用团队本地用例库

公开仓库不随附任何设备专属测试用例。团队需要执行自己的 JSON 用例时，在启动脚本前设置环境变量：

运行环境：Windows / PowerShell。

```powershell
$env:MESHTASTIC_CASES_PATH = 'D:\TeamTestAssets\meshtastic-cases.json'
.\start_dashboard.ps1
```

该文件应由团队在受控目录维护，不应提交到公开仓库。未设置变量时，页面不会加载测试项，但配置写入、通信验证、联系人互识、日志和 BLE 功能仍可使用。

## 6. 边界与异常处理

- 本平台不替代射频、天线、功耗和结构专项测试。
- 初次用户体验、手机 App 交互和复杂现场异常需要人工测试与复核。
- 平台仍在迭代优化，若遇到问题，请保留设备信息、操作步骤、日志和 JSON 报告，再进行缺陷分析。
