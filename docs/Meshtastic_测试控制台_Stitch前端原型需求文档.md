# Meshtastic 测试控制台 Stitch 前端原型需求文档

版本：v1.0  
日期：2026-09-09  
用途：交给 Stitch 绘制高级感前端原型图  
范围：仅定义前端信息架构、页面布局、视觉风格与交互规范  
后端约束：后端逻辑保持不变，不新增测试逻辑，不改变现有接口语义

## 1. 项目定位

Meshtastic 测试控制台是一个本地化测试工具，用于辅助测试人员完成 Meshtastic 设备的 CLI 环境检查、串口识别、设备配置读取、配置写入、通信验证、报告查看和串口日志旁路监听。

当前前端需要从“所有功能集中在一个页面”调整为“分区清晰、流程明确、适合长期测试使用”的后台工具型界面。

核心目标：

- 降低测试人员理解成本。
- 避免串口、报告、日志、测试项全部堆在同一屏。
- 支持单设备和双设备场景自动适配。
- 强化测试运行过程中的状态反馈。
- 让测试结果、失败原因、命令证据和日志证据可追溯。
- 保持极简、高级、稳定的后台工具风格。

## 2. 运行模式说明

现有“开启实机完整模式”命名不清晰，建议前端替换为“运行模式”。

运行模式使用分段控件（Segmented Control）呈现。  
VibeHub 术语参考：[分段控件](https://vibe-hub.org/segmented)。

### 2.1 预演

含义：

- 不需要连接设备。
- 仅展示测试流程、命令计划和报告结构。
- 不读取设备、不写配置、不发送消息。

后端参数映射：

```text
execute=false
allowMutating=false
```

### 2.2 实机只读

含义：

- 需要连接至少一台设备。
- 可执行 CLI 环境检查、设备身份读取、配置读取、频道读取、公钥读取。
- 不允许写配置，不允许发送消息。

后端参数映射：

```text
execute=true
allowMutating=false
```

### 2.3 实机可写

含义：

- 需要连接设备。
- 允许写配置、导入联系人、发送消息。
- 适合正式测试。
- 对可能导致设备重启的操作，需要在界面中明确提示“设备可能重启，请等待生效”。

后端参数映射：

```text
execute=true
allowMutating=true
```

## 3. 页面列表

整体采用左侧栏布局（Sidebar），但侧边栏必须是“悬浮岛式侧边栏”，不贴屏幕边缘。  
VibeHub 术语参考：[左侧栏布局](https://vibe-hub.org/sidebar-layout)。

页面列表：

| 页面 | 作用 | 访问频率 |
| --- | --- | --- |
| 工作台 | 展示当前环境、设备、最近结果和快捷入口 | 高 |
| 设备连接 | 扫描串口、分配设备、查看设备当前配置 | 高 |
| 测试运行 | 执行测试前检查、配置写入、通信验证 | 高 |
| 报告中心 | 查看、筛选、打开、下载历史报告 | 中 |
| 高级取证 | 执行低频排查动作，例如完整配置快照、NodeDB、命令证据 | 低 |
| 系统设置 | 查看 CLI 环境、日志目录、报告目录、默认参数 | 低 |

## 4. 全局布局

### 4.1 页面结构

桌面端推荐布局：

```text
窗口
├── 悬浮岛式侧边栏
│   ├── 工作台
│   ├── 设备连接
│   ├── 测试运行
│   ├── 报告中心
│   ├── 高级取证
│   └── 系统设置
└── 主内容区
    ├── 页面标题区
    ├── 页面核心内容
    └── 右侧详情抽屉，仅在需要时打开
```

### 4.2 悬浮岛式侧边栏

要求：

- 不贴屏幕边缘。
- 距离左侧和顶部保持 16-24px。
- 宽度建议 220-260px。
- 圆角建议 16px。
- 背景为白色或半透明浅色。
- 有轻微边框和阴影。
- 当前页面高亮清晰。
- 展开态显示图标和文字。
- 窄屏可收起为图标栏。

视觉表现：

- 像悬浮导航卡片，而不是传统贴边后台菜单。
- 不使用大面积深色侧栏。
- 不使用复杂渐变或装饰图形。

### 4.3 主内容区

要求：

- 主内容区与侧边栏保持明显间距。
- 单页只承载一个核心任务。
- 不将串口、日志、报告、测试项全部堆在同一页。
- 页面顶部固定展示当前运行模式和后端连接状态。
- 重要操作按钮放在模块右上角或底部固定操作区。

## 5. 视觉风格

整体风格：极简后台工具风。

关键词：

- Minimal Admin Tool
- Calm Dashboard
- Floating Island Sidebar
- Dense but Clear
- Soft Contrast
- Operational UI
- Low Decoration
- High Readability
- Professional QA Console

### 5.1 色彩

推荐色彩：

| 用途 | 色彩建议 |
| --- | --- |
| 页面背景 | `#F6F7F5` / `#F4F6F8` |
| 主卡片背景 | `#FFFFFF` |
| 一级文字 | `#111827` |
| 二级文字 | `#5B6472` |
| 边框 | `#D8DEE8` |
| 主操作 | 深绿色 `#137A4B` |
| 警告 | 琥珀色 `#B7791F` |
| 失败 | 深红色 `#B83A3A` |
| 成功 | 绿色 `#168A5A` |

禁止：

- 大面积紫色、蓝紫渐变。
- 大面积深蓝灰。
- 过多阴影。
- 装饰性光斑、圆球、背景图案。

### 5.2 字体

要求：

- 中文优先，技术名词保留英文。
- 字重不超过 3 档：Regular / Medium / Semibold。
- 不使用过大的标题。
- 不使用负字距。
- 数字、COM 口、Node ID、公钥使用等宽字体或半等宽样式。

### 5.3 文案语言

统一中文结果：

| 当前混用写法 | 统一写法 |
| --- | --- |
| PASS | 通过 |
| FAIL | 失败 |
| SKIP / SKIPPED | 跳过 |
| DRY | 预演 |
| RUNNING | 运行中 |
| Ready | 待运行 |

可保留英文技术词：

- CLI
- COM
- TCP
- BLE
- NodeDB
- Region
- Modem Preset
- Frequency Override

## 6. 页面详细需求

## 6.1 工作台

### 页面目标

让测试人员快速了解当前测试台状态，并进入常用任务。

### 模块结构

```text
工作台
├── 顶部状态栏
│   ├── 后端服务状态
│   ├── 当前运行模式
│   └── 最近同步时间
├── 状态总览
│   ├── CLI 状态
│   ├── 已识别设备数量
│   ├── 最近一次测试结果
│   └── 当前报告目录
├── 快捷入口
│   ├── 扫描设备
│   ├── 执行测试前检查
│   ├── 进入通信验证
│   └── 查看报告中心
└── 最近测试记录
    ├── 最近 3 条结果
    └── 点击进入报告详情
```

### 空状态

- 未扫描设备：显示“尚未扫描设备，请进入设备连接页扫描串口。”
- 无测试记录：显示“暂无测试记录，完成测试后会在这里显示。”

### 交互

- 点击快捷入口跳转对应页面。
- 最近测试记录可点击，打开报告详情抽屉。
- 工作台不展示复杂日志和命令证据。

## 6.2 设备连接

### 页面目标

完成连接方式选择、串口扫描、设备分配、设备当前配置展示。

### 模块结构

```text
设备连接
├── 连接方式
│   ├── 不连接设备
│   ├── 串口
│   ├── TCP
│   └── BLE
├── 串口扫描
│   ├── 扫描按钮
│   ├── COM 口列表
│   └── 状态标签
├── 设备分配
│   ├── 测试设备 1
│   └── 测试设备 2
├── 设备当前配置
│   ├── 设备 1 配置卡片
│   └── 设备 2 配置卡片
└── 串口日志旁路入口
```

### 串口列表字段

每个串口卡片展示：

- COM 口，例如 `COM7`
- 设备名称或 USB 描述，过滤乱码
- 状态：未分配 / 设备 1 / 设备 2 / 日志旁路

禁止展示：

- 乱码 USB 实例字符串。
- `#E504 - COMx` 这类拼接设备名。

### 设备命名规则

设备名称优先级：

1. 设备读取到的 Short Name。
2. 设备读取到的 Long Name。
3. 节点 ID 后四位。
4. 未读取成功时显示“未识别设备”。

COM 口只作为辅助信息展示，例如：

```text
8e5c
COM7
```

不要展示为：

```text
#8E5C - COM7
测试设备1 #8E5C - COM7
```

### 设备当前配置字段

设备当前配置卡片展示：

- Short Name
- Long Name
- 节点 ID
- 固件版本
- 硬件型号
- 本设备公钥
- Device Role
- Region
- Frequency Override
- Modem Preset
- Channel
- WiFi
- Bluetooth
- GPS

页面必须显示：

- 最后读取时间。
- 当前配置不是实时刷新。
- 点击“刷新配置”后重新读取。

## 6.3 测试运行

### 页面目标

执行测试前检查、配置写入、通信验证。

### 模块结构

```text
测试运行
├── 运行模式
│   ├── 预演
│   ├── 实机只读
│   └── 实机可写
├── 测试前检查
├── 配置写入
├── 通信验证
└── 执行结果
```

### 测试前检查

单设备场景：

- CLI 环境检查。
- 读取测试设备身份。
- 读取本设备公钥。
- 读取通信关键配置。
- 读取频道快照。

双设备场景：

- CLI 环境检查。
- 读取测试设备 1 身份。
- 读取测试设备 2 身份。
- 读取两台设备本设备公钥。
- 读取两台设备通信关键配置。
- 读取两台设备频道快照。
- 检查两台设备配置是否一致。
- 可选检查 NodeDB 可见性。

要求：

- 只连接一台设备时，不执行测试设备 2 的步骤。
- 只连接一台设备时，不显示双设备检查项。
- 前置检查失败时，结果卡片需要可点击查看失败详情。

### 配置写入

配置项保留常用字段，不展示过多低频字段。

保留字段：

- User name
- Region
- Modem Preset
- Channel
- Device Role
- WiFi
- Bluetooth
- GPS
- Language

Region 需要合并 Frequency Override：

```text
Region
├── Region 下拉选择
└── Frequency Override MHz 输入框
```

要求：

- Frequency Override 显示当前默认值。
- 支持用户手动修改。
- 如果用户不修改，则保持当前值。
- 写入前先读取当前配置。
- 如果当前配置与目标配置一致，不重复写入。
- 写入后等待设备重启完成，再读取验证。
- 写入流程内部步骤不在主结果列表拆开展示，只在详情中展示。

Language 仅展示：

- English
- 日本語
- 简体中文

### 通信验证

通信模式：

- 发送到频道
- 点对点发送
- 双向发送

字段：

- 发送方式
- 发送频道，仅在“发送到频道”时显示
- 消息内容，默认空
- 接收等待秒数，默认 10s
- 配置后等待秒数，默认 10s

要求：

- 用户不输入消息时，允许发送空消息。
- 双向发送时，两台设备发送同一条消息。
- 未选择新配置时，直接校验当前两台设备配置是否一致，再执行通信。
- 选择新配置时，先下发配置，等待生效，再执行通信。
- 已收到消息后，不应再执行会导致设备重启的非必要读取或写入操作。
- 主结果只显示最终用例结果，不拆分展示“读取、写入、等待、发送”等内部步骤。

通信结果判定：

- 发送到频道：至少一台目标设备监听到对应消息。
- 点对点发送：目标设备监听到发送方消息。
- 双向发送：两台设备均监听到对方消息。
- 如果两台设备都未收到消息，必须判定失败。
- 不能仅凭 CLI 返回码为 0 判定通过。

## 6.4 报告中心

### 模块结构

```text
报告中心

│   ├── 日期范围

│   ├── 设备名称
│   └── 结果状态
├── 报告列表
└── 报告详情抽屉
```

### 报告列表字段

- 时间
- 测试类型
- 设备
- 运行模式
- 最终结果
- 耗时

### 报告详情

展示：

- 测试摘要
- 最终结果
- 失败原因
- 设备信息
- 配置快照
- 通信方向
- 消息内容
- 命令证据
- 串口日志片段
- 报告文件路径
- 下载按钮

要求：

- 点击报告卡片打开详情，不重新打开当前网页。
- 下载按钮必须明确可用。
- 报告保存目录需要展示在页面中。

## 6.5 高级取证

### 页面目标

收纳低频排查工具，避免干扰主测试流程。

原“可选取证”改为“高级取证”。

### 模块结构

```text
高级取证
├── 配置字段可读性验证
├── 完整配置快照导出
├── NodeDB 可见性检查
├── 命令证据查看
└── 串口日志旁路监听
```

### 设计要求

- 默认不运行。
- 不放在测试运行页主流程里。
- 每个取证项需要说明是否只读。
- 涉及敏感字段时需要隐藏私钥、PSK、密码。

## 6.6 系统设置

### 页面目标

展示本地测试环境和默认参数。

### 模块结构

```text
系统设置
├── CLI 环境
│   ├── Meshtastic CLI 路径
│   ├── CLI 版本
│   └── Python 环境
├── 目录设置
│   ├── 报告目录
│   └── 日志目录
├── 默认测试参数
│   ├── 默认运行模式
│   ├── 默认接收等待秒数
│   └── 默认配置后等待秒数
└── 风险提示
    ├── 写配置可能导致设备重启
    └── 发送消息需要实机可写模式
```

## 7. 交互规范

## 7.1 空状态

### 未扫描设备

文案：

```text
未发现设备，请连接设备后扫描串口。
```

操作：

- 显示“扫描串口”按钮。
- 不显示测试设备 2 的相关内容。

### 未选择设备

文案：

```text
请选择测试设备后继续。
```

操作：

- 实机只读和实机可写模式下，测试按钮禁用。
- 预演模式下允许继续。

### 没有报告

文案：

```text
暂无报告，完成测试后会自动生成。
```

### 没有日志

文案：

```text
日志旁路未启动。
```

## 7.2 加载状态

### 串口扫描

- 扫描按钮显示 loading。
- 串口列表显示骨架屏。
- 扫描完成后列表淡入。

### 设备读取

- 设备卡片显示“读取中”。
- 禁止重复点击刷新。
- 超时后显示失败原因。

### 测试运行

展示：

- 当前测试项。
- 当前步骤。
- 总进度。
- 停止运行按钮。

未知进度时：

- 使用不确定进度条。
- 不显示虚假的百分比。

### 报告加载

- 报告列表显示骨架屏。
- 详情抽屉打开时显示局部 loading。

## 7.3 按钮反馈

主按钮：

- 点击后 120ms 内进入 loading。
- loading 期间禁用重复点击。
- 成功后短暂显示“已完成”。
- 失败后恢复可点击，并显示失败原因。

停止按钮：

- 运行中才显示。
- 点击后文案变为“停止中”。
- 停止完成后恢复默认状态。

危险操作：

- 写配置、导入联系人、发送消息只在“实机可写”模式启用。
- 非可写模式下按钮禁用，并通过 tooltip 说明原因。

## 7.4 卡片层级

卡片层级必须克制。

一级卡片：

- 页面核心模块，例如“配置写入”“通信验证”。

二级卡片：

- 设备卡片。
- 报告卡片。
- 测试结果卡片。

三级内容：

- 命令证据。
- 原始日志。
- 失败详情。

三级内容建议使用详情抽屉或折叠区，不要继续套卡片。

禁止：

- 卡片套卡片套卡片。
- 每个字段都做成独立大卡片。
- 同一页同时展示所有模块的完整内容。

## 7.5 文字动效

要求：

- 状态文字切换使用淡入淡出。
- 数字统计使用 200ms 以内递增动画。
- 日志按行追加，不使用打字机效果。
- 错误原因不做动画，直接展示。
- 不使用会影响阅读的循环文字动画。

## 7.6 元素进场动画

页面进入：

- 主内容淡入。
- 向上移动 6px。
- 时长 160-220ms。

悬浮侧边栏进入：

- 淡入。
- 从左侧轻微滑入。
- 时长 180ms。

结果卡片出现：

- 淡入。
- 向上移动 4-6px。
- 时长 150ms。

详情抽屉：

- 从右侧滑入。
- 时长 200ms。

## 7.7 动画终止逻辑

必须定义所有动画的结束条件：

- 测试完成后，进度条停止。
- 测试失败后，loading 停止。
- 用户点击停止运行后，按钮进入“停止中”，后端返回后终止动画。
- 报告加载完成后，骨架屏消失。
- 串口日志自动滚动仅在用户停留在底部时启用。
- 用户向上滚动日志时，暂停自动滚动。
- 支持系统 `prefers-reduced-motion`，关闭非必要动画。

## 8. 响应式规则

### 桌面端

- 左侧悬浮岛式侧边栏展开。
- 主内容区最大宽度 1180-1320px。
- 详情抽屉从右侧打开。

### 中等宽度

- 侧边栏收窄，只显示图标和当前页面名称。
- 页面内容由双栏变为单栏。

### 移动端

- 侧边栏变为底部导航或顶部抽屉。
- 表格转为列表卡片。
- 长日志默认折叠。

## 9. 关键验收标准

- 页面不再把所有功能堆在同一个视图。
- 侧边栏是悬浮岛式，不贴屏幕边缘。
- “开启实机完整模式”替换为“运行模式”。
- 预演、实机只读、实机可写三种模式含义清楚。
- 只连接一台设备时，只展示和执行单设备流程。
- 设备名称只显示真实设备名、Short Name 或节点 ID 后四位。
- 不显示乱码 USB 实例字符串。
- 不显示 `#E504 - COMx` 这类拼接名称。
- 配置写入只保留常用字段。
- Frequency Override 合并到 Region 中。
- 通信测试结果只展示最终通过或失败。
- 内部步骤、命令证据、日志证据放在详情中。
- 报告中心可打开详情并下载报告。
- 高级取证从主测试流程中拆出。
- 全平台中文一致，不混用英文状态词。
