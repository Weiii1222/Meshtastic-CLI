# 运行指南

本指南说明如何在 Windows 本地启动 Meshtastic 固件测试执行台。平台支持串口回归辅助、单设备 BLE 验证、串口日志和 JSON 报告；MeshCore 仍为规划能力。

## 1. 前置条件

- Windows 10/11。
- Python 3.10 或更高版本，安装时勾选加入 PATH。
- Git。
- 串口操作需要目标设备 USB 驱动、可识别的 COM 口和未被占用的设备。
- BLE 操作需要支持 Web Bluetooth 的浏览器；一次仅连接一台同类 Meshtastic 设备。

## 2. 安装

运行环境：Windows / PowerShell。

执行前置操作：关闭占用设备的手机 App、串口终端和其他 Meshtastic 工具。

```powershell
git clone https://github.com/Weiii1222/Meshtastic-test-platform.git
cd Meshtastic-test-platform

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install meshtastic
```

## 3. 启动

运行环境：Windows / PowerShell；在项目根目录执行。

```powershell
.\start_dashboard.ps1
```

浏览器打开 <http://127.0.0.1:8765>。预期页面顶部显示“服务正常”。前端文件修改后可用 `Ctrl+F5` 强制刷新；修改 `src/dashboard/server.py` 后需要重启脚本。

## 4. 首次验证

运行环境：Windows / PowerShell；在项目根目录执行，已创建 `.venv`。

```powershell
# 后端和执行器语法检查
.\.venv\Scripts\python.exe -m py_compile src\executor\runner.py src\executor\safe_meshtastic_cli.py src\dashboard\server.py

# 不连接设备的 dry-run；不传 --execute 不会操作设备
.\.venv\Scripts\python.exe src\executor\runner.py --custom-only --config-field device.role --config-value CLIENT
```

预期：语法检查无输出；dry-run 报告状态为 `DRY_RUN` 或 `SKIPPED`，仅证明执行器可以生成计划和报告，不表示真实硬件通过。

## 5. 常见问题

| 现象 | 处理 |
| --- | --- |
| 页面无法打开 | 确认 PowerShell 窗口未关闭；重新执行 `./start_dashboard.ps1`。 |
| 找不到 `.venv\Scripts\python.exe` | 在项目根目录重新执行 `python -m venv .venv`。 |
| 串口不可用 | 关闭其他串口工具和手机 App；重新扫描；确认设备重启后 COM 口没有变化。 |
| BLE 连接失败 | 只保留一台同类设备的 BLE 连接；断开其他手机/电脑后重新扫描。 |
| 写入后读到旧配置 | 适当增加写入后等待时间，再执行读回。 |
| 未显示团队测试项 | 设置 `MESHTASTIC_CASES_PATH` 指向团队本地 JSON 用例库，然后重启平台。 |
