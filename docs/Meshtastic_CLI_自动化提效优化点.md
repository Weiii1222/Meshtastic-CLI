# Meshtastic CLI 自动化提效优化点

更新时间：2026-09-04

## 当前结论

Wio Tracker L2 的 Meshtastic 固件可以用 CLI 覆盖一部分高重复、低观察成本的测试，但不能只靠 CLI 覆盖触屏、按键、声音、地图流畅度、屏幕显示等人工观察项。当前控制台应优先提升以下三类效率：

- 测试前环境和双设备状态取证。
- 通信变量配置下发与读回校验。
- 频道/点对点消息发送证据保存。

## 立刻可优化

1. **前置检查快照化**
   - 一次读取两台设备 `--info`，解析 Short Name、节点 ID、固件、硬件、Role、Region、Modem Preset、Frequency Override、WiFi、Bluetooth、GPS、MQTT、Channels。
   - 页面展示摘要，完整脱敏 JSON 保存在报告里。

2. **减少重启和串口冲突**
   - 写配置前先读当前值，相同则跳过 `--set`。
   - 同一台设备的多个配置字段合并成一条 CLI 写入命令。
   - 写后等待设备恢复，再读回校验。
   - 真实设备命令之间加入短间隔，降低 USB 刚枚举完成又被打开的失败率。

3. **通信测试按场景拆分**
   - 频道通信：适合验证公频/默认频道，只要求两台设备 Region、频率、Modem Preset、频道参数一致。
   - 点对点通信：适合验证公钥互识关系，必须有 ACK；NAK、MAX_RETRANSMIT、PKI_SEND_FAIL_PUBLIC_KEY 均判失败。

4. **结果可追溯**
   - 结果区只显示最终用例 PASS/FAIL。
   - 子步骤、stdout/stderr、配置读回、频道列表进入展开证据和 JSON 报告。
   - PASS/FAIL/SKIP/DRY 统计卡可筛选对应用例。

## 需要外部能力后再做

1. **设备屏幕 OCR / 摄像头观察**
   - 用于自动判定是否真正收到消息、屏幕频道名称、语言切换、地图白屏、黑屏等。

2. **按键/触屏执行器**
   - 用于自动覆盖 WAKE、U/B、Reset、触屏导航、设置菜单切换。

3. **串口日志旁路监听**
   - 用于确认发送消息是否导致异常重启、LoRa 收发日志、ACK/NAK 细节。

4. **统一测试台配置**
   - 设置固定日志目录 `MESHTASTIC_DASHBOARD_LOG_DIR`。
   - 固定 USB Hub 端口，记录 USB serial/location 与设备标签映射。
   - 每次执行前清理占用串口的软件和网页连接。

## 不建议自动化的边界

- 不用 CLI 自行判断“屏幕上是否看见消息”，除非接入 OCR/摄像头。
- 不用 `psk=random` 做双设备一致性配置，因为两台设备可能生成不同 PSK。
- 不把 NodeDB 里第一个节点当作测试设备；测试设备身份只能来自对应串口的本机 `--info`。
